Temp.c Feedback

1. The buffer size in Spi_SetupEB was hard coded instead of using the defined constant, this could make the update of the software difficult in future and the values could get mismatched in future updates.
2. The orinigal divide by 4 to shift by 2 bits gave the right answer for the positive temperatures but it was not correct for negative integers as we need to preserve sign, so first I changed the raw value to signed and then instead of divide by 4 I used bit shift by 2 which does the same thing but preserves the sign for negative value.
3. There is no unique error flag to catch wrong manufacturer id, or error data for manufacturer id which could make it difficult when it comes to fault diagnosis specially if we use the same error flag as data receive error. A unique error flag will point to the particular error due to wrong manufacturer id.
4. Access to a timer would have been helpful as right now the code has no way of rechecking the manufacturer ID during the whole program, as a glitch in even wrong filler bits of the manufacturer ID could lead to ID_checked flag to remain false for the whole program and that would mean the program can't go ahead and read temperature. A timer started when wrong id detected would have helped to re read manufacturer id using timer interrupt after the decided delay and that could help the program to get the right ID with re tries and resume the remaining program.
5. No function to access the manufacturer ID was given or mentioned in the TO DO. So the task scope needs questioning, are just storing the ID or do we need it to be accessed by the program? The TempSensor_Diagnostic_Services_Get_Temperature() function shows how to give access to the sensor data, so I will be happy to implement it if required.
